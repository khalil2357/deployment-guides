Infrastructure Guide

How to Implement Automated Subdomains Using Coolify and Cloudflare

Make <slug>.yourapp.com go live automatically the moment a customer signs up — no manual DNS or reverse-proxy setup per customer — using Cloudflare for DNS and Coolify to deploy.

Overview

The whole process, in six steps

Everything below this point goes deeper on each step. This is the shape of the full implementation, start to finish.

  1. See why a wildcard domain fails. Coolify turns *.yourapp.com into a Traefik rule that Traefik itself rejects — every subdomain 503s. Details →
  2. Build a provisioning service. A small class that calls Coolify's API to add one literal domain at a time. Details →
  3. Call it when a tenant is created. Fire addDomain() right after the tenant's database transaction commits. Details →
  4. Set three environment variables. COOLIFY_API_URL, COOLIFY_API_TOKEN, COOLIFY_APP_UUID. Details →
  5. Whitelist them in docker-compose. A variable set only in Coolify's dashboard still won't reach the container otherwise. Details →
  6. Redeploy once, then forget about it. Every tenant created after that provisions its own subdomain automatically. Details →
SECTION 01

The wildcard subdomain problem

Most SaaS products give each customer a subdomain, like acme.yourapp.com. The obvious way to route all of them to one server is a single wildcard domain: *.yourapp.com.

This does not work on Coolify. A wildcard domain turns into a Traefik rule using HostSNI, and Traefik rejects wildcards there:

invalid value for HostSNI matcher, '*.yourapp.com' is not a valid hostname

The router never registers, so every subdomain returns a 503. This is a known, unfixed Coolify bug (see References). The only reliable fix is a separate, literal domain per customer — acme.yourapp.com, not a wildcard.

Adding each domain by hand in the Coolify dashboard works, but does not scale. This guide covers doing it automatically, through Coolify's API, the moment a tenant is created.

SECTION 02

The fix, in short

When a tenant is created (and again if its slug is renamed), the backend calls Coolify's API to add <slug>.yourapp.com as a domain on the frontend app. Same action as the dashboard button, just automatic.

SECTION 03

Where the logic lives

Three pieces:

  • A service class (CoolifyService) that calls Coolify's API with fetch(). It reads its config from environment variables, exposes an isConfigured flag, and never throws.
  • That service registered in your tenant module, so it can be injected wherever a subdomain needs adding or removing.
  • Two call sites: addDomain() right after a new tenant's transaction commits, and addDomain(newSlug) + removeDomain(oldSlug) on rename.
Why outside the transaction The API call is slow and external. Run it after the database transaction commits, never inside it.
SECTION 04

How the slug is used

Each tenant has a unique, URL-safe slug — lowercase, no spaces, checked for uniqueness before the row is created. It is used in three places:

WhereHow
Tenant record Stored as the tenant's slug column, used to resolve requests to the right tenant.
Domain table A row stores the full subdomain (${slug}.yourapp.com) against the tenant, independent of whether Coolify has registered it yet.
Provisioning call The same string is passed to addDomain(), and later to removeDomain() on rename.

The provisioning service only ever handles the full domain string, never the raw slug.

SECTION 05

The provisioning service

Reads config once, exposes whether it's usable, and degrades to a no-op with a logged warning if not configured — instead of crashing the app.

subdomain-provisioner.service.ts
import { Injectable, Logger } from '@nestjs/common';

@Injectable()
export class CoolifyService {
  private readonly logger = new Logger(CoolifyService.name);

  private readonly apiUrl: string;
  private readonly apiToken: string;
  private readonly appUuid: string;
  private readonly isConfigured: boolean;

  // Coolify's domain PATCH replaces the whole list, it doesn't append.
  // Queue every call so two requests can't race and clobber each other.
  private queue: Promise<void> = Promise.resolve();

  constructor() {
    this.apiUrl = (process.env.COOLIFY_API_URL || '').replace(/\/$/, '');
    this.apiToken = process.env.COOLIFY_API_TOKEN || '';
    this.appUuid = process.env.COOLIFY_APP_UUID || '';
    this.isConfigured = Boolean(this.apiUrl && this.apiToken && this.appUuid);

    if (!this.isConfigured) {
      this.logger.warn('Coolify API not configured — add subdomains manually.');
    }
  }

  addDomain(domain: string): Promise<void> {
    if (!this.isConfigured) return Promise.resolve();
    this.queue = this.queue.then(() => this.addDomainInner(domain));
    return this.queue;
  }

  removeDomain(domain: string): Promise<void> {
    if (!this.isConfigured) return Promise.resolve();
    this.queue = this.queue.then(() => this.removeDomainInner(domain));
    return this.queue;
  }

  private headers() {
    return {
      Authorization: `Bearer ${this.apiToken}`,
      'Content-Type': 'application/json',
    };
  }

  private appEndpoint() {
    return `${this.apiUrl}/api/v1/applications/${this.appUuid}`;
  }

  private async getCurrentDomains(): Promise<string[]> {
    const res = await fetch(this.appEndpoint(), { headers: this.headers() });
    if (!res.ok) throw new Error(`Coolify GET failed: ${res.status}`);
    const data = await res.json();
    return String(data.fqdn || '')
      .split(',')
      .map((d: string) => d.trim())
      .filter(Boolean);
  }

  private async patchDomains(domains: string[]): Promise<void> {
    const res = await fetch(this.appEndpoint(), {
      method: 'PATCH',
      headers: this.headers(),
      body: JSON.stringify({ domains: domains.join(','), instant_deploy: true }),
    });
    if (!res.ok) throw new Error(`Coolify PATCH failed: ${res.status}`);
  }

  private async addDomainInner(domain: string): Promise<void> {
    try {
      const full = `https://${domain}`;
      const current = await this.getCurrentDomains();
      if (current.includes(full)) return;

      await this.patchDomains([...current, full]);

      // Coolify can silently drop a PATCH. Re-read, retry once if needed.
      const verify = await this.getCurrentDomains();
      if (!verify.includes(full)) {
        await this.patchDomains([...current, full]);
      }
    } catch (error) {
      this.logger.error(`Failed to add domain ${domain}`, error as Error);
    }
  }

  private async removeDomainInner(domain: string): Promise<void> {
    try {
      const full = `https://${domain}`;
      const current = await this.getCurrentDomains();
      const next = current.filter((d) => d !== full);
      if (next.length === current.length) return;
      await this.patchDomains(next);
    } catch (error) {
      this.logger.error(`Failed to remove domain ${domain}`, error as Error);
    }
  }
}
SECTION 06

Adding a domain, step by step

  1. Read current domains. GET /api/v1/applications/{uuid}, read the fqdn field.
  2. Check if already present. If https://<slug>.yourapp.com is already in the list, stop — safe to retry anytime.
  3. Write the full updated list. PATCH /api/v1/applications/{uuid} with the old domains plus the new one, and instant_deploy: true. This is a full replace, not an append.
  4. Read it back to confirm. Coolify can return success without the change actually saving.
  5. Retry once if it didn't stick. If it still fails, log it and move on — never throw.
SECTION 07

Removing a domain

removeDomain() does the reverse: read the list, filter out the domain, PATCH the shorter list back. Used in two cases:

  • Slug rename — call addDomain(newDomain) first, then removeDomain(oldDomain), so the tenant is never without a working subdomain.
  • Tenant deleted — its subdomain should stop routing to your app.
SECTION 08

Environment variables

COOLIFY_API_URL=https://coolify.yourdomain.com
COOLIFY_API_TOKEN=<a Coolify API token with write access to applications>
COOLIFY_APP_UUID=<the frontend application's UUID in Coolify>
VariableWhere to find it
COOLIFY_API_URLYour Coolify instance's base URL.
COOLIFY_API_TOKEN Coolify → avatar → API Tokens → create one with write access to applications.
COOLIFY_APP_UUID Shown in the app's dashboard URL, or via GET /api/v1/applications.

If any of the three are missing, isConfigured is false and both methods silently do nothing. Tenant creation is unaffected either way.

SECTION 09

The docker-compose gotcha

The most common mistake Setting these variables in Coolify's dashboard is not enough if you deploy with docker-compose. Compose files often whitelist which variables actually reach the container.

If your service looks like this:

services:
  backend:
    environment:
      - DATABASE_URL=${DATABASE_URL}
      - JWT_SECRET=${JWT_SECRET}
      # anything not listed here never reaches process.env

a variable missing from this list is invisible to your app, even if it's set in Coolify's dashboard. Any new variable needs its own line here too.

Checklist:

  1. Add the three Coolify variables to the compose file's environment list.
  2. Paste the same values into Coolify's dashboard.
  3. Redeploy the backend app (not the frontend).

These three steps are one-time. Every tenant created after that provisions automatically.

SECTION 10

Full flow on tenant creation

  1. Customer signs up with slug acme.
  2. Backend commits the tenant, its settings, and a domain record for acme.yourapp.com.
  3. coolifyService.addDomain('acme.yourapp.com') fires in the background — not awaited by the response.
  4. Coolify applies new Traefik rules and, because of instant_deploy: true, redeploys the frontend app.
  5. The redeploy takes one to two minutes. Until then, acme.yourapp.com still 503s — expected, not a bug.
  6. Once redeployed, acme.yourapp.com serves the real app.
SECTION 11

Troubleshooting a 503

First, check if the domain actually registered:

curl -s -H "Authorization: Bearer $COOLIFY_API_TOKEN" \
  "$COOLIFY_API_URL/api/v1/applications/$COOLIFY_APP_UUID" \
  | jq -r '.fqdn' | tr ',' '\n' | grep <slug>
ResultMeaning
Not in the list The call never fired or failed — check the compose whitelist gotcha above. Register it manually with the PATCH below as a stopgap.
In the list, still 503 Still redeploying. Wait a minute. If it's been much longer, check the app's deploy logs in Coolify.

Manual fallback:

BASE="$COOLIFY_API_URL/api/v1/applications/$COOLIFY_APP_UUID"
CURRENT=$(curl -s -H "Authorization: Bearer $COOLIFY_API_TOKEN" "$BASE" | jq -r '.fqdn')
curl -X PATCH "$BASE" \
  -H "Authorization: Bearer $COOLIFY_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d "{\"domains\": \"${CURRENT},https://<slug>.yourapp.com\", \"instant_deploy\": true}"
SECTION 12

Security notes

Treat this token as a secret A Coolify API token with write access can redeploy your app and change its domains. Handle it like a database password.
  • Never commit a file with real environment values. Check the exact filename against your .gitignore — don't assume it's covered.
  • Keep example/template env files free of real values, even temporarily.
  • If a credential is ever exposed, rotate it. Deleting it from the file later does not remove it from git history.
  • Scope the API token as narrowly as Coolify allows — write access to one app, not full admin access, if that option exists.
